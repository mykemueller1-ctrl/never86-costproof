# Capture a real sponsor run

The public Node application is the competition build. Use this repository's commands and source records. A separate Python prototype and its 27-test deck were prepared in another Codex session. Their $280/$200/$120 bridge and $490 correction example are not this application's scenario and must not be shown as its output.

## One execution command

After the real local services and reviewed source mapping are ready, run from this repository:

```powershell
node --experimental-transform-types src/live-run.mjs
```

The command loads the local ignored `.env`, checks configuration, uses the actual application investigator and critic, and saves `live.receipt.json` plus the returned `live.trace.json` under the ignored `.costproof/live/` directory. It uses a fresh memory directory to keep prior reports out of this baseline check. The existing memory suite separately proves reviewed-report recall across a process restart.

It requires all of these observations to pass:

- Registered synthetic sales, labor and policy records returned through real Zetaris network requests, with reviewed mapping and matching source identifiers.
- A real Nightshift discovery, source plan, explanation and critic response.
- Accepted model critique and exact numeric validation in the application.
- The canonical shift scope and its $600 gap.

Fixture mode, injected test transport, missing sources, a rejected critic and model discovery without text cannot pass. The process has a four-minute hard deadline. A deadline stops the process with a blocked error and no completed receipt; it cannot be counted as a pass. A normal failure exits nonzero and preserves a blocked receipt without raw provider errors or credentials.

## Remaining machine setup

The source snapshot reports Nightshift 1.2.1 installation, successful routing discovery and a `no_provider_configured` text response on the Windows development machine. Finish installing/configuring a working local provider in Nightshift. Discovery alone is insufficient.

Finish WSL/Docker startup for Zetaris, then follow [the source setup](zetaris-provider.md) and [synthetic HTTP helper](zetaris-fixture-http/README.md). The participant must create the API key in the actual instance. No key is created, inferred or bundled by this repository. A reviewed mapping file is not evidence of a successful source query by itself.
